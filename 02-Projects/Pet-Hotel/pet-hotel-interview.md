# Pet Hotel Management Interview Questions

Technology:

- React.js
- JavaScript
- Node.js
- MongoDB


---

# 1. Project Overview


## Q1. ช่วยอธิบายโปรเจกต์ Pet Hotel ให้ฟังหน่อย


## 🗣️ แนวตอบ

Pet Hotel เป็นระบบจัดการร้านรับฝากสัตว์เลี้ยงครับ

ผู้ใช้สามารถสมัครสมาชิก เพิ่มข้อมูลสัตว์เลี้ยง จองห้องพัก ตรวจสอบสถานะการจอง และติดตามการดูแลสัตว์เลี้ยงได้ครับ

ส่วน Admin และ Staff สามารถจัดการข้อมูลสัตว์เลี้ยง การจอง และการ Check-in / Check-out ได้ครับ


---

## Q2. ระบบนี้แก้ปัญหาอะไร?


## 🗣️ แนวตอบ

ระบบช่วยลดการจัดการข้อมูลแบบ Manual เช่น การจดข้อมูลสัตว์เลี้ยงและการจองด้วยกระดาษ

ช่วยให้เจ้าของสัตว์เลี้ยงสามารถตรวจสอบข้อมูลและสถานะการจองได้ง่ายขึ้นครับ


---

## Q3. User ในระบบมีใครบ้าง?


## 🗣️ แนวตอบ

ระบบแบ่งเป็น 3 Role หลักครับ

1. Customer
- จองบริการ
- เพิ่มข้อมูลสัตว์เลี้ยง
- ดูประวัติ


2. Staff
- จัดการ Check-in
- ดูแลสัตว์เลี้ยง


3. Admin
- จัดการข้อมูลระบบ
- จัดการ User และ Report


---

## Q4. User Flow เป็นอย่างไร?


## 🗣️ แนวตอบ

Customer สมัครสมาชิก

↓

เพิ่มข้อมูลสัตว์เลี้ยง

↓

เลือกวันเข้าพัก

↓

ระบบตรวจสอบข้อมูล

↓

สร้าง Booking

↓

Staff ตรวจสอบและ Check-in

↓

Check-out และชำระเงิน


---

# 2. System Architecture


## Q5. อธิบาย Architecture ของระบบ


## 🗣️ แนวตอบ

ระบบแบ่งเป็น 3 ส่วนครับ

Frontend ใช้ React สำหรับสร้างหน้าจอและรับข้อมูลจาก User

Backend ใช้ Node.js สำหรับสร้าง API และจัดการ Business Logic

Database ใช้ MongoDB สำหรับเก็บข้อมูลสัตว์เลี้ยง User และ Booking ครับ





---

## Q6. ทำไมเลือกใช้ MongoDB?


## 🗣️ แนวตอบ

เลือก MongoDB เพราะเป็น NoSQL Database ที่เก็บข้อมูลแบบ Document ครับ

เหมาะกับข้อมูลที่มีโครงสร้างยืดหยุ่น เช่น ข้อมูลสัตว์เลี้ยงที่อาจมีรายละเอียดแตกต่างกัน

และสามารถพัฒนาได้รวดเร็วครับ


---

# 3. React Frontend


## Q7. ทำไมเลือก React?


## 🗣️ แนวตอบ

เลือก React เพราะสามารถแบ่งหน้าเว็บเป็น Component ได้ครับ

ทำให้จัดการ UI ง่าย และสามารถนำ Component กลับมาใช้ซ้ำได้


---

## Q8. Component คืออะไร?


## 🗣️ แนวตอบ

Component คือส่วนย่อยของหน้าเว็บครับ

เช่น Navbar, Booking Card หรือ Pet Card

ช่วยให้โค้ดเป็นระบบและแก้ไขง่ายครับ


---

## Q9. State ใช้ทำอะไรในระบบ?


## 🗣️ แนวตอบ

ใช้เก็บข้อมูลที่มีการเปลี่ยนแปลง เช่น

- ข้อมูล User Login
- ข้อมูลสัตว์เลี้ยง
- รายการ Booking
- Loading Status


---

## Q10. เรียก API อย่างไร?


## 🗣️ แนวตอบ

Frontend จะส่ง Request ไป Backend ผ่าน API

เมื่อได้รับข้อมูลกลับมา จะนำมาเก็บใน State และแสดงผลบนหน้าเว็บครับ


---

# 4. Booking System


## Q11. ระบบ Booking ทำงานอย่างไร?


## 🗣️ แนวตอบ

เมื่อ Customer เลือกวันเข้าพัก ระบบจะตรวจสอบข้อมูลสัตว์เลี้ยงและพื้นที่ว่างก่อน

ถ้าข้อมูลถูกต้องจะสร้าง Booking และรอการยืนยันจาก Staff ครับ


---

## Q12. ป้องกันการจองซ้ำอย่างไร?


## 🗣️ แนวตอบ

ตรวจสอบจำนวนพื้นที่ว่างก่อนสร้าง Booking ครับ

และตรวจสอบซ้ำที่ Backend เพื่อป้องกัน User หลายคนส่ง Request พร้อมกัน


---

## Q13. ถ้ามี User จองพร้อมกันหลายคนทำอย่างไร?


## 🗣️ แนวตอบ

Backend ต้องเป็นตัวควบคุมครับ

ใช้การตรวจสอบข้อมูลก่อนบันทึก และใช้ Database Transaction หรือ Lock ข้อมูลเพื่อป้องกันการจองเกินจำนวนครับ


---

# 5. MongoDB


## Q14. MongoDB คืออะไร?


## 🗣️ แนวตอบ

MongoDB เป็น NoSQL Database ที่เก็บข้อมูลในรูปแบบ Document คล้าย JSON ครับ

ทำให้สามารถเก็บข้อมูลที่มีโครงสร้างเปลี่ยนแปลงได้ง่าย


---

## Q15. Collection คืออะไร?


## 🗣️ แนวตอบ

Collection เปรียบเหมือน Table ใน SQL ครับ

ใช้เก็บกลุ่มของ Document ที่มีรูปแบบใกล้เคียงกัน


---

## Q16. Document คืออะไร?


## 🗣️ แนวตอบ

Document คือข้อมูลแต่ละรายการใน MongoDB ครับ

มีรูปแบบคล้าย JSON เช่น ข้อมูล User หรือข้อมูลสัตว์เลี้ยง


---

## Q17. Reference กับ Embed ต่างกันอย่างไร?


## 🗣️ แนวตอบ

Embed คือเก็บข้อมูลรวมกันใน Document เดียว

Reference คือแยกข้อมูลออกจากกันแล้วเชื่อมด้วย ID

ถ้าข้อมูลมีการใช้งานร่วมกันหลายจุด มักใช้ Reference ครับ


---

# 6. Feature


## Q18. ระบบตรวจสอบวัคซีนทำงานอย่างไร?


## 🗣️ แนวตอบ

ระบบเก็บข้อมูลวัคซีนของสัตว์เลี้ยงไว้ครับ

ก่อนอนุญาตให้เข้าพัก ระบบจะตรวจสอบว่าครบตามเงื่อนไขหรือไม่

ถ้าไม่ครบจะแจ้งให้เจ้าของดำเนินการก่อนครับ


---

## Q19. Upload รูปสัตว์เลี้ยงทำอย่างไร?


## 🗣️ แนวตอบ

Frontend ส่งไฟล์ไป Backend

Backend ตรวจสอบประเภทและขนาดไฟล์

จากนั้นเก็บไฟล์หรือเก็บ URL เพื่อเรียกใช้งานครับ


---

## Q20. แบ่ง Zone ห้องพักอย่างไร?


## 🗣️ แนวตอบ

ระบบแบ่ง Zone ตามประเภทสัตว์เลี้ยงครับ

เช่น Cat, Small Dog และ Large Dog

เมื่อจอง ระบบจะตรวจสอบประเภทสัตว์เลี้ยงและเลือกพื้นที่ที่เหมาะสมครับ


---

## Q22. Validation ทำอย่างไร?


## 🗣️ แนวตอบ

Backend ป้องกันข้อมูลผิดหรือข้อมูลที่ถูกส่งโดยตรง

# 8. Senior Question


## Q23. ถ้ามี User 1,000 คนใช้งานพร้อมกัน?


## 🗣️ แนวตอบ

ต้องดูว่า Bottleneck อยู่ตรงไหนครับ

อาจเพิ่ม Database Index

ปรับ API

ใช้ Cache

หรือเพิ่ม Server เพื่อรองรับจำนวน User


---

## Q24. ถ้าข้อมูลสัตว์เลี้ยงเพิ่มขึ้นมาก?


## 🗣️ แนวตอบ

ควรออกแบบ Database ให้เหมาะสมครับ

เพิ่ม Index สำหรับข้อมูลที่ค้นหาบ่อย

และจัดการ Query ให้มีประสิทธิภาพ


---

## Q25. ถ้าทำใหม่จะปรับอะไร?


## 🗣️ แนวตอบ

ผมจะวาง Database Structure ให้ละเอียดขึ้น

เพิ่ม Automated Testing

และปรับระบบ Notification หรือ Real-time ให้ดีขึ้นครับ
