Project:
ระบบค้นหาลานจอดรถ (Smart Parking)

Technology:

- React.js

- Tailwind CSS

- Database

# 1. Project Role


## Q4. คุณรับผิดชอบส่วนไหน?


## 🗣️ แนวตอบ

ในโปรเจกต์นี้ผมรับผิดชอบทั้ง Frontend และ Backend ครับ

ฝั่ง Frontend ผมพัฒนาหน้าเว็บไซต์และเชื่อมต่อ API เพื่อแสดงข้อมูลและรับข้อมูลจากผู้ใช้งานครับ

ฝั่ง Backend ผมช่วยพัฒนา API และจัดการ Logic ของระบบ เช่น การรับข้อมูล การประมวลผล และการเชื่อมต่อ Database ครับ

รวมถึงช่วยออกแบบ Database และวิเคราะห์ Requirement ร่วมกับทีม เพื่อให้ระบบทำงานตามความต้องการของผู้ใช้งานครับ


---

# 2. System Architecture


## Q5. อธิบาย Architecture ของระบบ


## 🎯 ผู้สัมภาษณ์ต้องการรู้

- เข้าใจโครงสร้างระบบหรือไม่
- เข้าใจการทำงานระหว่าง Frontend และ Backend หรือไม่


## 📌 จำ

```text
User

↓

React Frontend

↓

REST API

↓

Node.js Backend

↓

Database
```


## 🗣️ แนวตอบ

ระบบแบ่งเป็น 3 ส่วนหลักครับ

ส่วนแรกคือ Frontend ใช้ React สำหรับสร้างหน้าจอและจัดการส่วนที่ผู้ใช้มองเห็น เช่น การค้นหาที่จอดรถ การจอง และการแสดงข้อมูลครับ

ส่วนที่สองคือ Backend ใช้ Node.js เป็นตัวกลางในการจัดการ Business Logic และสร้าง API สำหรับรับส่งข้อมูลระหว่าง Frontend กับ Database ครับ

ส่วนสุดท้ายคือ Database ใช้สำหรับจัดเก็บข้อมูล เช่น User, Parking, Booking และ Payment ครับ


---

# Q6. ทำไมต้องแยก Frontend กับ Backend?


## 🎯 ผู้สัมภาษณ์ต้องการรู้

เข้าใจหลักการออกแบบระบบหรือไม่


## 🗣️ แนวตอบ

การแยก Frontend และ Backend ทำให้แต่ละส่วนสามารถพัฒนาและแก้ไขได้ง่ายขึ้นครับ

Frontend สามารถปรับเปลี่ยนหน้าจอหรือ User Interface ได้ โดยไม่กระทบกับ Logic ของระบบหลังบ้าน

ส่วน Backend สามารถนำ API ไปใช้กับ Client อื่น เช่น Mobile Application ในอนาคตได้ครับ


---

# 3. React Frontend


## Q7. ทำไมเลือก React?


## 🎯 ต้องการรู้

เข้าใจ Technology ที่เลือก


## 📌 จำ

- Component
- Reusable
- Maintain


## 🗣️ แนวตอบ

ผมเลือก React เพราะสามารถแบ่ง UI เป็น Component ได้ครับ

ทำให้สามารถนำส่วนต่าง ๆ กลับมาใช้ซ้ำได้ เช่น Button, Card หรือ Navbar

และช่วยให้ Code มีโครงสร้างที่ดูแลและพัฒนาต่อได้ง่ายขึ้นครับ


---

## Q8. Component คืออะไร?


## 🗣️ แนวตอบ

Component คือส่วนประกอบย่อยของหน้าเว็บไซต์ครับ

เช่น Navbar, Button, Card หรือส่วนแสดงข้อมูลต่าง ๆ

React สามารถแยกแต่ละส่วนเป็น Component เพื่อให้จัดการง่าย และสามารถนำกลับมาใช้ใหม่ได้ครับ


---

## Q9. State คืออะไร?


## 📌 จำ

ข้อมูลที่เปลี่ยนแปลงได้


## 🗣️ แนวตอบ

State คือข้อมูลภายใน Component ที่สามารถเปลี่ยนแปลงค่าได้ครับ

เมื่อ State มีการเปลี่ยนแปลง React จะทำการ Render UI ใหม่ เพื่อแสดงข้อมูลล่าสุดให้กับผู้ใช้งานครับ


---

## Q10. ใช้ State จัดการอะไรในระบบ?


## 🗣️ แนวตอบ

ในระบบ Smart Parking ใช้ State สำหรับจัดการข้อมูลที่มีการเปลี่ยนแปลง เช่น

- ข้อมูล User ที่ Login
- ข้อมูลช่องจอดที่ผู้ใช้เลือก
- สถานะ Loading
- ข้อมูลที่ได้รับจาก API

ครับ


---

## Q11. useEffect ใช้ทำอะไร?


## 🗣️ แนวตอบ

useEffect ใช้สำหรับจัดการ Side Effect หลังจาก Component Render ครับ

เช่น การเรียก API เพื่อโหลดข้อมูลลานจอด การดึงข้อมูล User หรือการติดตามค่าที่เปลี่ยนแปลงครับ


---

## Q12. เรียก API จาก Frontend อย่างไร?


## 🗣️ แนวตอบ

Frontend จะส่ง Request ไปยัง Backend API ผ่าน HTTP Method เช่น GET หรือ POST ครับ

หลังจาก Backend ประมวลผลแล้ว จะส่ง Response กลับมา

Frontend จะนำข้อมูลที่ได้มา Update State และแสดงผลบนหน้าเว็บไซต์ครับ


---

## Q13. Routing ทำอย่างไร?


## 🗣️ แนวตอบ

ใช้ React Router สำหรับจัดการเส้นทางของหน้าเว็บไซต์ครับ

เช่น

- Login
- Parking
- Booking
- Profile

ทำให้สามารถเปลี่ยนหน้าได้โดยไม่ต้อง Reload ทั้งเว็บไซต์ครับ


---

## Q14. ทำ Validation อย่างไร?


## 🎯 ผู้สัมภาษณ์ต้องการรู้

เข้าใจเรื่องความปลอดภัยหรือไม่


## 🗣️ แนวตอบ

ผมตรวจสอบข้อมูลเบื้องต้นที่ Frontend เพื่อช่วย User Experience ครับ

เช่น ตรวจสอบข้อมูลว่าง หรือรูปแบบข้อมูล

แต่จะตรวจสอบซ้ำที่ Backend อีกครั้ง เพราะข้อมูลจาก Frontend สามารถถูกแก้ไขได้ครับ


---

# 4. Backend Node.js


## Q15. Node.js ทำหน้าที่อะไร?


## 🗣️ แนวตอบ

Node.js ทำหน้าที่เป็น Backend Server ครับ

ใช้สำหรับสร้าง API ติดต่อกับ Frontend และจัดการ Logic ของระบบ เช่น Login, Booking และการจัดการข้อมูลจาก Database ครับ


---

## Q16. REST API คืออะไร?


## 📌 จำ

Frontend ↔ Backend


## 🗣️ แนวตอบ

REST API คือรูปแบบการสื่อสารระหว่าง Client และ Server ผ่าน HTTP Protocol ครับ

ใช้สำหรับส่งและรับข้อมูลระหว่าง Frontend กับ Backend


ตัวอย่าง Method:

- GET ใช้อ่านข้อมูล
- POST ใช้สร้างข้อมูล
- PUT/PATCH ใช้แก้ไขข้อมูล
- DELETE ใช้ลบข้อมูล


---

## Q17. Middleware คืออะไร?


## 🗣️ แนวตอบ

Middleware คือ Function ที่ทำงานระหว่าง Request และ Response ครับ

ใช้สำหรับตรวจสอบหรือจัดการข้อมูลก่อนส่งไปยัง Controller เช่น

- ตรวจสอบ Token
- ตรวจสอบ Permission
- จัดการ Error


---

## Q18. JWT คืออะไร?


## 🗣️ แนวตอบ

JWT เป็น Token ที่ใช้สำหรับยืนยันตัวตนของผู้ใช้งานครับ

หลังจาก User Login สำเร็จ Backend จะสร้าง Token และส่งกลับไปให้ Frontend

เมื่อ User เรียก API ที่ต้องมีสิทธิ์ ระบบจะส่ง Token กลับมาให้ Backend ตรวจสอบก่อนอนุญาตให้ใช้งานครับ


---

## Q19. ถ้า Token หมดอายุทำอย่างไร?


## 🗣️ แนวตอบ

เมื่อ Token หมดอายุ ระบบสามารถให้ User Login ใหม่ได้ครับ

หรือใช้ Refresh Token เพื่อออก Token ใหม่โดยไม่ต้อง Login ใหม่ทุกครั้งครับ


---

## Q20. Error Handling ทำอย่างไร?


## 🗣️ แนวตอบ

ผมใช้การจัดการ Error เพื่อให้ระบบสามารถรับมือกับปัญหาได้ครับ

โดยตรวจสอบ Error และส่ง Status Code ที่เหมาะสมกลับไป เช่น

- 400 Bad Request
- 401 Unauthorized
- 404 Not Found
- 500 Internal Server Error

พร้อมข้อความที่ช่วยให้ Frontend แสดงผลกับผู้ใช้ได้ครับ
